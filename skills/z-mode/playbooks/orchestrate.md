# Orchestrate
You run the program, never the code. Decide which agent does each piece of work, then check what each one produces. Route here for a standing multi-day program: many stacked PRs, many workers, and few human turns. Use autonomous-run for work that one agent could finish inside the session's budget.

State the goal, units, dependencies, scope, budget, and authorized actions once. Run the program with your own tools: spawn workers through the [selected execution method](../references/native-hosts.md#execution-selection). Keep state in the host's native task tracker when it has one. Keep a short notes file in a user-owned directory such as `.agent-work/<slug>/notes.md`, outside delegated writes. Record goal, authority, standing directives, and each unit's owner, PR, head, and verdict. When Herdr is enabled, also record task-to-agent/pane assignments, with endpoint and live status kept separate from acceptance. Watch PRs with the host's native PR and CI event subscriptions when available. Call no bookkeeping scripts, run no polling loops, and never relay messages or status between agents.

## Topology
- **One owner per PR.** The owner is the only writer of its branch and carries the PR from build to merge within the user's authorized actions. Only the owner pushes, rebases, or retargets it. Closing or retargeting a base PR orphans every PR above it, so the owner does that only on your call. You never author or edit code. Conflicted merges, chain rebases, and fixes go to owners.
- **A fresh worker for each independent task,** under the [agent lifecycle rules](../references/native-hosts.md#agent-lifecycle). Its brief carries everything it needs, including each upstream report it depends on, pasted in full. Workers can't see their siblings. Give each writer an exclusive worktree or branch. Use host remote isolation only where available and permitted. Keep work local when it needs this machine: a local runtime check, local transcripts, a simulator, or auth that exists only here. Model settings follow the [delegation contract](../references/native-hosts.md#delegation).
- **A sub-coordinator only when one area has many parallel workers** and the host supports nesting. It owns that area's workers and briefs and sends you one rollup, never raw worker reports. Stop at three levels: you, sub-coordinators, and workers. Size the in-flight window under the lifecycle cap: start with 2-3 after the pilot. Widen only as host limits, user budget, and useful parallelism allow, to at most about ten per coordinator. Start the next one as each finishes rather than waiting on a whole batch.
- **Reuse a worker only for its built state,** such as its checkout, uncommitted changes, or a running process. Fork it where the host supports forks; otherwise use the lifecycle reuse exception. Every other follow-up or fix round goes to a fresh agent with a consolidated brief, because ownership is a role, not one agent. Never message a worker to check on it, because a message restarts an idle agent.
- **Each PR gets a verifier that isn't its author,** from another model family, through native delegation or the [other-provider route](../references/native-hosts.md#other-provider-route). The owner merges only on that verifier's pass at the current head, and only when the user authorized merges. Merges follow [Shipping](shipping.md), except that a stacked child's own owner does Shipping's retarget, rebase, and push of that child. Without merge authority or an other-family verifier, the PR stops at merge-ready and you report the gap.
- **Start with one unit.** Take it through brief, owner, verifier, and merge or merge-ready before you fan out. A flaw in the brief then costs one agent instead of fifty. On near-identical cheap units, the first unit is that test.

## Supervision
- **Each brief names the evidence that proves the work is done,** such as a command and its expected output, a verification-skill check, or an artifact. It also names the goal, the paths the worker may and may not write, and the actions it must not take. If you can't name the evidence, the unit isn't scoped yet.
- **Read the diff or the artifact, not only the worker's summary.** Green CI is an input to a verdict, not a verdict. Behavioral work needs more than a type check. A verdict covers one head SHA, so a new push needs a new verdict. Read a sample of each sub-coordinator's briefs while its workers run, and fix its instructions when one fails.
- **Send back work that drifts from scope or grows past what was asked.** Keep only the fixes that block the program, and park the rest as follow-ups.
- **Check a PR's live state before you report on it,** with `gh pr view` and `gh pr checks` or your forge's equivalents, not the worker's last report. Account for every worker you spawned as done, replaced, or absorbed into another worker's scope.
- **Stop or replace a worker that stalls or loops.** Judge it by its pushes and PR activity, not its status text or transcript mtime. Retry once with a fresh agent under the [agent lifecycle rules](../references/native-hosts.md#agent-lifecycle), with the brief corrected for the cause, such as a smaller scope after a context or memory limit. Then drop the unit, record the gap, and replan around it. When a stopped worker returns late, check its result against the PR's current state, and hand any unique findings to a fresh worker.
- **Ask the user only for a real decision or a blocker,** such as an action outside the granted authority, an irreversible action, a product or preference call that no experiment settles, or a dead end that survived a replan. Rebase mechanics, retries, CI flakes, review triage, and "should I keep going" never reach the user.
- **Reconcile every worker before completion or pause.** A host without a durable runtime gets a usable [pause-safely](pause-safely.md) handoff, not promised wakeups.

Return what landed against the goal, each PR's live state and verdict with its link, what was dropped and why, the decisions waiting on the user, and the notes path.
